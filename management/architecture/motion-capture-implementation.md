# モーションキャプチャー実装手順

## 概要
MediaPipeで取得したトラッキングデータを使用して、Unityのアバターを動かし、その動きを3Dデータとして取得するシステムの実装手順。

## 実装ステップ

### 1. データフローの構築
```
MediaPipe → Web → Unity → 3Dデータ
```

### 2. 各コンポーネントの実装

#### A. MediaPipe側（Web）
1. トラッキングデータの取得
   - 手のトラッキング
   - ポーズトラッキング
   - 顔のトラッキング

2. データの整形
   - 座標系の変換（MediaPipe → Unity）
   - クォータニオン/回転行列の計算
   - スケールの調整

3. データ送信
   - WebSocket/APIの実装
   - データ形式の定義
   - エラーハンドリング

#### B. Unity側
1. アバターの準備
   - ヒューマノイドアバターの設定
   - ボーン/リグの設定
   - アニメーションコントローラーの作成

2. データ受信システム
   - WebSocket/APIクライアントの実装
   - モーションデータの受信
   - データのバリデーション

3. モーション適用
   - アバターへのモーション適用
   - スムージング/補間処理
   - エラー時のフォールバック

4. 3Dデータ出力
   - アニメーションデータの保存
   - glb/fbx形式での出力
   - リアルタイムストリーミング

### 3. 技術仕様

#### A. データ形式
```typescript
interface MotionData {
  timestamp: number;
  pose: {
    keypoints: Array<{
      x: number;
      y: number;
      z: number;
      confidence: number;
    }>;
  };
  hands: {
    left: Keypoint[];
    right: Keypoint[];
  };
  face: {
    landmarks: Keypoint[];
  };
}
```

#### B. 通信仕様
1. WebSocket
   - ポート: 8080
   - プロトコル: ws://
   - データ形式: JSON

2. REST API（代替案）
   - エンドポイント: /motion
   - メソッド: POST
   - データ形式: JSON

### 4. 実装の優先順位
1. MediaPipeデータの整形と送信
2. Unity側の受信システム
3. アバターへのモーション適用
4. 3Dデータの出力
5. UI/UXの改善

### 5. 注意点
- レイテンシーの最小化
- データの精度とスムージング
- エラーハンドリング
- パフォーマンス最適化
